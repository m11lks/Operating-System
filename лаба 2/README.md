# Лабораторная работа №2. Управление виртуальной памятью и проецируемые файлы

Работа посвящена двум темам:

1. **Управление виртуальной памятью процесса**: сведения о системе и памяти, резервирование и передача (commit) регионов, запись в память, защита страниц, освобождение.
2. **Обмен данными между процессами через проецируемый в память файл** (memory-mapped file): процесс-сервер пишет данные, процесс-клиент их читает.

## Состав

| Файл | Платформа | Что делает |
|---|---|---|
| [`lab2_main.cpp`](lab2_main.cpp) | Windows (Win32 API) | Меню для работы с виртуальной памятью: `VirtualAlloc`, `VirtualQuery`, `VirtualProtect`, `VirtualFree` |
| [`lab2_linux_server.cpp`](lab2_linux_server.cpp) | Linux (`mmap`) | Сервер: создаёт файл, отображает его в память и пишет туда строку |
| [`lab2_linux_client.cpp`](lab2_linux_client.cpp) | Linux (`mmap`) | Клиент: отображает тот же файл и читает строку, записанную сервером |

## Windows: `lab2_main.cpp`

### Меню

| Пункт | Действие | Используемые функции |
|---|---|---|
| 1 | Информация о системе | `GetSystemInfo` |
| 2 | Состояние памяти | `GlobalMemoryStatus` |
| 3 | Состояние региона по адресу | `VirtualQuery` |
| 4 | Выделение памяти | `VirtualAlloc` (`MEM_RESERVE`, `MEM_COMMIT`) |
| 5 | Запись данных по адресу | `VirtualQuery` + прямая запись `int` |
| 6 | Установка защиты | `VirtualProtect` |
| 7 | Освобождение памяти | `VirtualFree(..., MEM_RELEASE)` |
| 0 | Выход | — |

### Подробнее

- **`GetSystemInfo`**: размер страницы, тип и число процессоров, маска активных процессоров, минимальный и максимальный адреса, доступные приложению.
- **`GlobalMemoryStatus`**: процент загрузки памяти, объём физической памяти, файла подкачки и виртуального адресного пространства (всего и свободно, в МБ).
- **`VirtualQuery`** по введённому шестнадцатеричному адресу показывает:
  - базовый адрес региона и базу выделения, размер региона;
  - состояние: `MEM_COMMIT`, `MEM_RESERVE` или `MEM_FREE`;
  - тип: `MEM_IMAGE` (образ exe/dll), `MEM_MAPPED` (проецируемый файл) или `MEM_PRIVATE`;
  - атрибуты защиты (`Protect`).
- **Выделение памяти** можно провести двумя способами:
  - **раздельно**: сначала `MEM_RESERVE`, затем по нажатию Enter `MEM_COMMIT` того же региона. Между шагами можно в другом пункте меню посмотреть, что регион находится в состоянии `MEM_RESERVE`;
  - **одновременно**: `MEM_RESERVE | MEM_COMMIT` за один вызов.

  Адрес выбирается автоматически (`NULL`) или задаётся вручную. После выделения можно сразу освободить регион.
- **Запись в память**: перед записью программа через `VirtualQuery` проверяет, что регион передан (`MEM_COMMIT`) и доступен на запись (`PAGE_READWRITE` / `PAGE_EXECUTE_READWRITE`). Иначе выводятся текущее состояние или защита, и записи не происходит.
- **`VirtualProtect`**: можно выставить `PAGE_NOACCESS`, `PAGE_READONLY`, `PAGE_READWRITE`, `PAGE_EXECUTE`, `PAGE_EXECUTE_READ` или `PAGE_EXECUTE_READWRITE`. Выводится старая защита, новая проверяется повторным `VirtualQuery`.

### Сценарий для демонстрации

1. Пункт 4 → раздельно → автоматический адрес → запомнить выданный адрес, пока не нажимать Enter.
2. Пункт 4 → Enter → память передана, освобождать пока не нужно (0).
3. Пункт 3 → ввести адрес → состояние `MEM_COMMIT`, защита `0x4` (`PAGE_READWRITE`).
4. Пункт 5 → записать число → успех.
5. Пункт 6 → `PAGE_READONLY` → пункт 5 → запись отклонена с выводом текущей защиты.
6. Пункт 7 → освободить → пункт 3 → состояние `MEM_FREE`.

### Сборка

```bash
g++ lab2_main.cpp -o lab2_main.exe
```

## Linux: `lab2_linux_server.cpp` и `lab2_linux_client.cpp`

Межпроцессный обмен через общий файл `n_file.dat`, который оба процесса отображают в память с флагом `MAP_SHARED`. Это аналог `CreateFileMapping` / `MapViewOfFile` в Windows.

### Сервер

| Пункт | Действие |
|---|---|
| 1 | `open(O_CREAT)` → `ftruncate` до 4096 байт → `mmap(PROT_READ \| PROT_WRITE, MAP_SHARED)` |
| 2 | Запись строки `"Hello, shared memory!"` прямо в отображённую память |
| 3 | `munmap`, `close`, удаление файла (`unlink`), выход |

### Клиент

| Пункт | Действие |
|---|---|
| 1 | `open` существующего файла → `mmap` с `MAP_SHARED` |
| 2 | Ожидание через `select()` с таймаутом 5 с, затем вывод содержимого общей памяти |
| 3 | `munmap`, `close`, выход |

Благодаря `MAP_SHARED` изменения, сделанные сервером, сразу видны клиенту без явных `read`/`write`.

> Для обычного файла `select()` всегда сообщает о готовности сразу. Ожидание здесь формальное: фактически клиент читает то, что уже лежит в общей памяти.

### Сборка и запуск

```bash
g++ lab2_linux_server.cpp -o server
```

```bash
g++ lab2_linux_client.cpp -o client
```

Запускать в двух терминалах из одного каталога. Порядок такой:

1. сервер: пункт 1 (mapping), затем пункт 2 (запись);
2. клиент: пункт 1 (mapping), затем пункт 2 (чтение);
3. клиент: пункт 3, затем сервер: пункт 3 (сервер удаляет файл).
