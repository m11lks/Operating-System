# Лабораторная работа №3. Многопоточное вычисление числа π

Число π вычисляется численным интегрированием методом прямоугольников (средних точек):

$$
\pi = \int_0^1 \frac{4}{1+x^2}\,dx \approx \frac{1}{N}\sum_{i=0}^{N-1} \frac{4}{1+x_i^2}, \qquad x_i = \frac{i + 0.5}{N}
$$

- число итераций: **N = 100 000 000**;
- итерации раздаются потокам **блоками по 4 316 020**;
- замер проводится для **1, 2, 4, 8, 12 и 16 потоков**.

Задача работы: реализовать одно и то же вычисление двумя способами (вручную через Win32 API и через OpenMP) и сравнить время и ускорение.

## Состав

| Файл | Платформа | Что делает |
|---|---|---|
| [`lab3_win.cpp`](lab3_win.cpp) | Windows (Win32 API) | Ручное управление потоками: `CreateThread`, события, `SuspendThread` / `ResumeThread` |
| [`lab3_openmp.cpp`](lab3_openmp.cpp) | Кроссплатформенно (OpenMP) | `#pragma omp parallel for` с редукцией и динамическим расписанием |

Обе программы выводят таблицу одного формата:

```
| Threads |      Pi Result      | Time (ms) | Speed (M.iter/sec) |
```

---

## Windows: `lab3_win.cpp`

Блоки распределяются динамически: поток, закончивший свой блок, берёт следующий.

- **Счётчик блоков** `std::atomic<int> next_block`. Поток атомарно берёт номер очередного блока через `fetch_add(1)`, поэтому два потока не получат один и тот же блок.
- **Частичные суммы** каждый поток копит в своей ячейке `total_sum[id]`, так что синхронизация при сложении не нужна.
- **Синхронизация с главным потоком** устроена через события с автосбросом (`CreateEvent`):
  1. поток считает блок, сигналит своё событие `SetEvent(doneEvents[id])` и приостанавливает сам себя `SuspendThread(GetCurrentThread())`;
  2. главный поток ждёт, пока все события будут подняты (`WaitForMultipleObjects(..., TRUE, ...)`);
  3. если блоки ещё остались, главный поток будит всех через `ResumeThread`, и цикл повторяется;
  4. когда блоки кончились, поток сигналит событие и выходит.
- Результат: сумма всех `total_sum[i]`, делённая на `N`. Время замеряется через `std::chrono::high_resolution_clock`.

### Сборка

```bash
g++ -O2 lab3_win.cpp -o lab3_win.exe
```

## OpenMP: `lab3_openmp.cpp`

То же вычисление в одну директиву:

```cpp
#pragma omp parallel for reduction(+:pi) schedule(dynamic, block_size)
```

- `omp_set_num_threads(n)` задаёт число потоков для очередного прогона;
- `reduction(+:pi)`: у каждого потока своя копия `pi`, в конце копии складываются;
- `schedule(dynamic, block_size)`: блоки по 4 316 020 итераций раздаются потокам по мере освобождения, как и в Win32-версии;
- время замеряется через `omp_get_wtime()`.

### Сборка

Linux:

```bash
g++ -O2 -fopenmp lab3_openmp.cpp -o lab3_openmp
```

Windows (MinGW):

```bash
g++ -O2 -fopenmp lab3_openmp.cpp -o lab3_openmp.exe
```

MSVC:

```bash
cl /EHsc /O2 /openmp lab3_openmp.cpp
```

## Что сравнивать

- **Корректность**: во всех строках таблицы π должно совпадать с 3.1415926535… до 9–10 знаков.
- **Ускорение** `S(n) = T(1) / T(n)`: рост примерно до числа физических или логических ядер, затем насыщение.
- **Накладные расходы** ручной схемы (приостановка и возобновление потоков после каждого блока) по сравнению с OpenMP.
