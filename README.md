# Операционные системы: лабораторные работы

Лабораторные работы по дисциплине «Операционные системы» за семестр. Все программы написаны на C++ и представляют собой консольные приложения. Основная часть сделана на **Win32 API**, часть заданий дополнительно реализована под **Linux** (POSIX) и на **OpenMP**.

## Содержание

| № | Тема | Windows (Win32 API) | Linux / кроссплатформенно |
|---|---|---|---|
| [1](лаба%201/README.md) | Управление файловой системой, асинхронный ввод-вывод | Диски, тома, каталоги, файлы, атрибуты и время файлов | Асинхронное копирование файла через POSIX AIO с замером скорости |
| [2](лаба%202/README.md) | Виртуальная память, проецируемые файлы | `VirtualAlloc` / `VirtualQuery` / `VirtualProtect` / `VirtualFree` | Обмен между процессами через `mmap` (сервер и клиент) |
| [3](лаба%203/README.md) | Многопоточность: вычисление π | Потоки `CreateThread` + события + `Suspend`/`ResumeThread` | OpenMP: `parallel for` + `reduction` |
| [4](лаба%204/README.md) | Синхронизация процессов, именованные каналы | Читатели и писатели на семафорах и общей памяти, named pipe с overlapped I/O | — |

## Кратко о каждой работе

### [Лабораторная №1. Файловая система и асинхронный ввод-вывод](лаба%201/README.md)

- **Windows** ([`labwin1.cpp`](лаба%201/labwin1.cpp)): меню для работы с файловой системой. Список дисков, тип диска, информация о томе и свободном месте, создание и удаление каталогов, создание, копирование и перемещение файлов, чтение и изменение атрибутов и времени файла.
- **Linux** ([`lablin2.cpp`](лаба%201/lablin2.cpp)): копирование файла цепочками `aio_read` → `aio_write` с уведомлением через `SIGEV_THREAD`. Замер скорости в зависимости от размера блока и числа одновременных операций (1–16).

### [Лабораторная №2. Виртуальная память и проецируемые файлы](лаба%202/README.md)

- **Windows** ([`lab2_main.cpp`](лаба%202/lab2_main.cpp)): сведения о системе и памяти, состояние региона по адресу, резервирование и передача памяти (раздельно и одновременно), запись в память с проверкой прав, смена защиты страниц, освобождение.
- **Linux** ([`lab2_linux_server.cpp`](лаба%202/lab2_linux_server.cpp), [`lab2_linux_client.cpp`](лаба%202/lab2_linux_client.cpp)): сервер отображает файл в память (`mmap`, `MAP_SHARED`) и пишет строку, клиент отображает тот же файл и читает её.

### [Лабораторная №3. Многопоточное вычисление π](лаба%203/README.md)

Интегрирование `4/(1+x²)` на [0, 1], N = 10⁸ итераций, блоки по 4 316 020 итераций, прогоны на 1, 2, 4, 8, 12 и 16 потоках.

- **Win32** ([`lab3_win.cpp`](лаба%203/lab3_win.cpp)): динамическая раздача блоков через атомарный счётчик, синхронизация событиями, приостановка и возобновление потоков.
- **OpenMP** ([`lab3_openmp.cpp`](лаба%203/lab3_openmp.cpp)): `#pragma omp parallel for reduction(+:pi) schedule(dynamic, block_size)`.

### [Лабораторная №4. Синхронизация процессов и именованные каналы](лаба%204/README.md)

- **Читатели и писатели** ([`disp.cpp`](лаба%204/disp.cpp), [`lab4_writer.cpp`](лаба%204/lab4_writer.cpp), [`lab4_reader.cpp`](лаба%204/lab4_reader.cpp)): диспетчер запускает N писателей и M читателей. Они работают с буфером из 12 страниц в общей памяти, каждую страницу охраняет пара семафоров. Состояния процессов с метками времени пишутся в логи.
- **Именованный канал** ([`lab4_server.cpp`](лаба%204/lab4_server.cpp), [`lab4_client.cpp`](лаба%204/lab4_client.cpp)): сервер пишет в `\\.\pipe\npipe` асинхронно с ожиданием события, клиент читает через `ReadFileEx` с completion-процедурой.

## Сборка

Отдельной системы сборки нет: каждый `.cpp` компилируется отдельно. Точные команды приведены в README каждой лабораторной. Общая схема:

Windows-программы (MinGW):

```bash
g++ file.cpp -o file.exe
```

Linux-программы:

```bash
g++ file.cpp -o file
```

Дополнительные флаги нужны в трёх случаях: `-lrt` для POSIX AIO (лаба 1), `-fopenmp` для OpenMP (лаба 3) и `-lwinmm` для писателя и читателя (лаба 4).
